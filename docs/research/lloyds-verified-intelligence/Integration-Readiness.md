## Operational evidence and negative tests

## What unlocks a genuine proof

1. Obtain original publisher bytes through an authorised acquisition path, preserve exact URL/date, hash those bytes and record minimal provenance; do not archive protected documents wholesale.
2. Existing Source ownership resolves the actual use/retention/publication scope, including material terms applicability. Do not infer approval from this commission or from a successful download.
3. Existing identity and resource owners supply the exact real canonical subject, workspace, membership and resource ACL. `SC095000`, `BK-ENT-001`, research slugs and test headers are not substitutes.
4. In an isolated, explicitly authorised store, use the existing package/review/plan/execute services. Preserve original research/Evidence identities and create an actual reviewed new source version where needed.
5. Use the existing presentation entry for that authorised context; test real revision withdrawal/correction, another actor/workspace/enterprise denial, repeat execution and retained history before proposing any public integration.

The conditional handoff requires no universal canonical promotion of lawful factual analysis. Stronger canonical execution/publication is still an existing-owner decision. No new financial run, Pipeline write, Source allowlist, approval registry or engine is introduced. A successful future isolated proof would still not itself authorise production activation.
