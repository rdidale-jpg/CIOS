The committed [division receipt](Proof-Division.json) and [AI receipt](Proof-AI.json) are sanitised deterministic test summaries. They are not publisher-byte archives, Source decisions, production import receipts or proof of real account access. The test file is [test_flora_lloyds_recovery_proof.py](../../../tests/test_flora_lloyds_recovery_proof.py).

## Implemented service path

The existing Initial Factory reads retained register anchors (four assertions, not fresh registry acquisition), prepares the commercial records and builds the existing Blueprint archive. The registry and validator stage 12 records per case: four register Evidence/Observation pairs plus two commercial pairs. Candidate review and a dry-run plan precede approval. The actual **existing** CanonicalPromotionService executes into temporary test repositories only. Existing Observation/model processing produces six attributes; its repeat execution returns `repeat_no_change`. The existing `route_replay`/`replay_sections` renders the candidate statements without a new runtime route or renderer.

The test proves that both statements are absent before execution and present afterwards, across their correct streams. It checks absent authority, wrong workspace, different actor, different enterprise and pilot-runtime denial; bad source entity/scope/date/checksum/withdrawal cannot be silently accepted. The held financial source is included as a negative input and stays out of staging. All writes are confined to the temporary `memory`, `blueprint_import` and `enterprise_canvas` roots; no Financial run or Pipeline store is created.

An Evidence withdrawal is an **isolated test operation** demonstrating the existing read-time filter. Correction changes the supporting statement deliberately; the Observation/attribute is no longer valid support and the statement disappears rather than silently inheriting the old assertion's authority. A real corrected assertion would require the existing reviewed update/supersession route; the test does not approve one automatically.

## Deliberate limits and separate Source proof

The selected replay's digest fingerprints repository claim bindings, **not authentic publisher document bytes**. We do not fabricate document digests or Source lifecycle receipts. Legacy `commercial_factory` replay records do not have the revision envelope consumed by `source_lifecycle.apply_source_lifecycle`; therefore automatic Source-revision withdrawal for these exact newly replayed candidates remains an **integration blocker**, not a claimed success. Explicit Evidence withdrawal works in both cases.

The already-existing `test_flora_verified_factory.py` separately exercises retained source-revision identifiers in an isolated fixture: missing lifecycle, withdrawn revision and changed digest suppress the existing candidate projection without rewriting historical Evidence/model data. Lloyds' retained responsible-AI assertion remains `attributed_only`, unlike the specifically corroborated Arm fixture; no automatic verified Lloyds handoff is claimed. This regression is rerun without changing the fixture or strengthening its authority.

The result is a successful reproducible **service-integration proof**, with publication/admission and legacy revision-binding limits explicit. There is no proof that Gold consumes these new model attributes or that production holds them; neither occurs in this sprint.
