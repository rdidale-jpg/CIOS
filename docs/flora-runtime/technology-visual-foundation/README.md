# UK Technology — governed visual foundation

Adds UK Technology to **Industries** in the existing FLORA shell. Start at `/industries/technology`. This is a visual implementation over recovered ChatGPT-led research, with a deterministic candidate handoff. Research completion and canonical acceptance remain separate gates.

## Delivered experience

- **How it works:** eight selectable visual roles, shared memberships, conceptual dependencies, role economics and provider drill-through. The eight population groups roll up to the Page's seven industry segments; memberships overlap and never encode market share or provider importance.
- **Who uses what:** 34 scoped programme/relationship records. Each retains the customer/participant, product/capability, provider/partner roles, source links, publication and event dates separately, date-only retrieval provenance, attribution and limitations. Plans, alliances and research collaborations do not become deployments or current contracts. The two Rolls-Royce data/AI cases remain separate.
- **Where work may emerge:** the final six evidence-linked briefs from the Page, each with consequences, possible intervention, alternative explanation and qualification questions. No capture endpoint or automatic Pipeline record.
- **Supporting views:** 80-view provider directory, five hypothetical reference operating models with links to attributed provider overlays, separate economic definitions, nine dated/Unknown timeline markers, inspectable Page passages, corrections/contradictions and open gaps.
- Server-rendered links and disclosures work without JavaScript. A small script opens the exact addressed evidence disclosure. No new front-end dependency or external asset request.

## Handoff and acceptance register

`Candidate-Handoff.json` is the deterministic output of `technology.handoff()` and is also inspectable at `/industries/technology/handoff`. This **is not a new importer or accepted package schema**. The adapter reuses the existing `SourceSegment`, `CandidateClaim` and `EvidencePackageItem` contracts for Page research inspection. The SourceSegment digest covers the actual retained Page row or paragraph. It never represents an unavailable original publisher document checksum. Unknown dates remain null; a date-only retrieval record is never expanded into an invented timestamp.

| Class | Recovered/represented | Eligible source import | Canonically accepted |
| --- | ---: | ---: | ---: |
| Provider views | 80 partial | 0 canonical entity bindings | 0 from this handoff |
| Programme / relationship rows | 34 drafts | 0 | 0 |
| Atomic passage references | 24 drafts | 0 | 0 |
| Commercial briefs | 6 unqualified interpretations | Not Evidence/Observation objects | 0 Pipeline records |

Every candidate is **withheld** with explicit reason codes: source-operation rights unresolved, exact source retrieval timestamps absent, publisher content not reacquired, unbound canonical identity, unaccepted Technology domain mapping, and (where applicable) publisher outside the existing allowlist. A Page link or short quote cannot satisfy the existing importer provenance contracts. No allowed publisher, review/promotion rule or confidence threshold was weakened.

- `research_intelligence/source_import.py`: source URL, provenance, bytes/excerpt and permission boundary.

- `blueprint_import/views.py`, existing Evidence mapping and `memory/models.py`: review, promotion and accepted Evidence/Observation ownership. Not invoked by this public projection.
- Existing `sales_pipeline.py`: deliberate authorised capture and qualification; no Technology producer or write route added.

The recovered pack stays with its review documentation outside the frozen accepted/reviewed research corpus. This preserves the exact 160-file historical inventory and every existing research identity. It is not a second canonical store.
