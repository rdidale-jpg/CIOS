# Capability-led transport understanding

The following is an **analyst decomposition**, not an internal enterprise organisation/system map. Individual dossiers distinguish sourced activity from conceptual capabilities and missing implementation detail. A durable capability is an ability to deliver an outcome; a programme changes it; a supplier/platform enables it. These categories are not interchangeable.

|Economic role|Value stream|Durable capabilities|People/process/data dependencies to verify|Actual technology/programme evidence|
|---|---|---|---|---|
|Rail infrastructure|Allocate access → inspect → prioritise → intervene → assure availability|Asset stewardship, safe work planning, maintenance delivery, network control|Asset engineers/planners; condition/work-order/possession/outcome records|Reach fibre/mobile agreement; not proof of all asset systems|
|Passenger operator|Plan service → ready crew/fleet → carry/recover → settle fares/fees|Service planning, crew competence, fleet readiness, disruption recovery|Depot/driver/control roles; duty/timetable/defect/demand records|FirstGroup mobilisation and driver training; sold Mistral asset not retained|
|Highway operator|Inspect → design treatment → schedule traffic management → deliver → measure|Asset intervention, incident response, work assurance, cost attribution|Inspectors/commercial teams; intervention depth/type, cost and output quality|ORR documents technology-renewal delays and reporting limits; no vendor inferred|
|Urban authority|Commission/operate integrated network → enable access → maintain service|Concession management, fare access, passenger information, accessibility|Operators/control/customer roles; journey, contract-performance and asset data|TfL Go; historical Siemens train/support programme; no new platform assumptions|
|Airline|Design network → sell → prepare → fly → recover → fulfil package|Revenue/network planning, safe flight operations, engineering, customer recovery|Crews/dispatch/engineering; flight/weather/performance/maintenance data|IAG SkyBreathe selection; easyJet existing Aviation source trail retained|
|Airport|Coordinate capacity → process passengers/cargo → turn aircraft → assure facilities|Airside/terminal coordination, security/baggage, facilities, commercial estate|Airline/handler/regulator roles; slots/stands/queues/asset service levels|Public technology-cost narrative does not identify contracts or a system estate|
|Port|Plan call → berth → handle/store → clear → dispatch rail/road|Quay/yard control, equipment availability, gate/rail coordination, property operation|Terminal workers/planners; vessel/container/dwell/equipment records|Gateway capacity/rail/BOXBAY announcement; ABP Spot-It! reported transition|
|Parcels/logistics|Collect/receive → sort/store → fulfil/transport → deliver → resolve/return|Routing, fulfilment, last-mile execution, exception/quality management|Couriers/warehouse staff; shipment/address/task/scan/outcome records|No named Royal Mail/DHL UK system or vendor verified; no generic platform treated as fact|

AI investigation is conditional on an evidenced decision bottleneck, lawful access to suitable data, safety/rights controls and measured net benefit. A plausible capability diagram is not proof of a current system failure or buying programme. No automatic Material Pressure, Opportunity or Pipeline handoff follows from these maps.
