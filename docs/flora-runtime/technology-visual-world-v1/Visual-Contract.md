# FLORA visual-world contract v1

Status: presentation contract for owner review. This is not a canonical intelligence schema, an accepted architecture decision or a new research engine. UK Technology is the first implementation. Banking, Aviation and Enterprise remain unchanged until separately authorised.

## Image as the navigation surface

An industry opens as one illustrated operating landscape. Districts, actors, flows and seams carry meaning; they are not decoration above a second dashboard. The same spatial world remains the anchor across lenses and provider/programme selections. Detail belongs in a secondary contextual overlay or disclosure, never in a default card grid.

The implementation marker is `data-scene-contract="flora-visual-world-v1"`. An SVG uses a responsive composition with an accessible title/description and native links. Wide and portrait compositions contain the same eight role identities and navigation targets, with unique DOM identifiers. Only the visible composition participates in normal interaction. Small screens can pan the compact landscape inside a bounded region and use the text alternative.

## Semantic grammar

| Visual primitive | Meaning | Required evidence boundary | Interaction |
| --- | --- | --- | --- |
| Illustrated district | Conceptual capability or operating role | Explicitly conceptual; layout never implies geography, enterprise ownership, provider importance or market share | Native link to role context and existing provider navigation |
| Fine landscape flow | Conceptual dependency | No inference of a particular deployment, contract or causal outcome | Orientates the scene; district endpoints are navigable |
| Blue programme ribbon | One attributed research programme | Exact retained record, customer/participant, offering, roles, publication/event dates and source boundaries; not accepted canonical fact | Either end opens the same programme context, then existing enterprise/evidence routes |
| Amber numbered seam | Unqualified commercial hypothesis | Evidence, alternative explanation, qualification question and related programmes/providers; no budget or buying intent inferred | Opens one hypothesis overlay, never a Pipeline producer |
| Provider marker | Selected research view within its explanatory role | Brand/group/legal identity remains unbound unless existing owners resolve it; overlapping membership is allowed | Opens partial profile and identity/source gaps while preserving the map |
| Context overlay | Secondary explanation and inspection | Visible status label and exact links to retained research provenance | Close/return link; native scrolling/disclosures; no new write action |

`data-truth-class` distinguishes `conceptual`, `attributed_report` and `hypothesis`. These are presentation labels. They must never be reused as Evidence acceptance, Observation lifecycle, Enterprise Model confidence or Pipeline qualification.

## Selection and navigation

Scene state is a bounded GET selection: lens, role, programme, provider or theme. Unknown values fail closed. Links are real URLs and work without JavaScript; they can be bookmarked, printed or followed with a keyboard. Existing public-route policy remains the authority. The only added selector is the finite `theme` key on the existing Technology route.

The image uses explanatory spatial placement, not inferred deployment geography. A programme ribbon is schematic and deliberately does not attach every named partner to every background district. Full unabridged research fields remain in context, while long scene labels use an explicit ellipsis. Existing enterprise navigation is reused exactly; unknown enterprise identities do not become new canonical objects.

## Progressive disclosure and accessibility

- Default lens: image, semantic legend, brief status and navigation instruction; no open detail panel.
- Selected role/provider/programme/theme: scene plus one contextual overlay. Overlay placement leaves the selected district or seam visible where practical; portrait layouts put detail below the scene.
- SVG links have names, titles, visible keyboard focus and generous hit regions. While keyboard focus is on an image link, an overlaid detail pane fades and stops intercepting the pointer so the scene target remains visible.
- A native text-navigation disclosure provides the same scene destinations. The programme chooser is labelled and works as a GET form.
- Distinctions use words, line treatment and shape as well as colour. No motion or external animation dependency is introduced; reduced-motion and print rules remain explicit.
- Browser evidence is Chromium at simulated desktop, landscape/portrait tablet and mobile sizes. Physical device, Safari and assistive-technology user acceptance require separate owner testing.

## Reuse for later industries and enterprises

Reuse the grammar, status boundary, keyboard behaviour, responsive composition and image/context hierarchy. Create illustrations around each system's actual operating story: money/payment/credit flows for Banking, aircraft/airport/turnaround operations for Aviation, and evidenced capabilities/programmes for an Enterprise. Do not simply recolour the Technology scene or apply its taxonomy to another industry.

Each future scene must adapt its existing governed read models into visual nodes and links. Conceptual relationships remain distinct from attributed evidence and hypotheses. No visual adapter may allocate canonical identities, generate accepted facts, broaden source policies, write Pipeline records or invoke an agent. Existing source, identity, correction, review, promotion and qualification owners remain authoritative.

## UK Technology acceptance boundary

The 80-view population, 34 programme/relationship records, six hypotheses, 24 bounded passage references, SourceSegment/CandidateClaim/EvidencePackageItem mapping, source-policy decisions and research limitations are byte-preserved from #570. This reset changes their presentation and navigation only. “Living” describes a navigable visual world; it does not mean live monitoring or independently verified current deployments.
