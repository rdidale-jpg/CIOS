## Source ownership and exact gates

`live/source_registry.SourceRecord` owns source registration. Existing `research_intelligence.primary_text`, provenance/official_url, SourceSegment/CandidateClaim and `macro.validate_context` own the public candidate contracts. EAI-1 uses fixed, hash-bound candidate files under the existing Banking/Macro source boundaries and validates **disposable copies**; it never revises the historical Assessment-Overlay, Macro-Context, understanding review or source records. No new intelligence store, Source registry or permissive renderer route is installed.

Six new proposal/excerpt files are admitted into the existing **research file inventory** by literal path/digest; that is technical proposed-corpus admission, not Evidence approval. All163 earlier source expectations, their byte comparator, unknown/ignored-file negatives, strict388 tests and CI failure baseline remain unchanged. Dependency pins preserve every previous claim/source fingerprint; additional pins are specific to these candidates and the two existing deposit facts.

Admission precedes titles/counts. Unknown versions, wrong issuer/subject, rights denial/revocation, owner-only material, stale/superseded/retracted/core-contradicted sources and missing excerpts remove the dependent view. Existing source-owner verification is always required; `presentation.eligible` alone cannot grant publisher rights. The bounded view review expires15December2026 until explicitly renewed.
