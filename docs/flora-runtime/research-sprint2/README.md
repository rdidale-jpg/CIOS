## What semantic assurance actually does

`foundation/sprint2/assurance.py` accepts a complete typed proposal and separate researcher/verifier passages, validates provenance and operation rights, independently recompiles bounded meaning from the verifier's complete passage and compares every proposition facet. The proof-eligible statement is generated by a total controlled renderer; arbitrary natural-language claims cannot piggyback on a few matching words.

The built-in semantic grammar covers controlled investment-plan statements and a narrow real HM Treasury announcement pattern. It understands planned versus achieved, scoped amounts rather than estimated benefits, geography and reporting period. In the real announcement, the GDP estimate's 2024–2028 period is **not transferred to the investment plan**: the plan's exact endpoints remain unspecified. A stale plan may be considered as an explicitly historical statement; it cannot be silently relabelled current.

One actual source proof accepts only the **historical announced £8bn AWS plan**. Five counterfactual support claims—achieved outcome, £14bn investment, France, deployment and the EMEA subsidiary—are rejected against that passage. This rejects unsupported support assertions; it is not proof that every counterfactual is absolutely false in the world. Government reporting of an enterprise announcement is not independent verification of its execution. No GDP/job estimate is an achieved outcome or procurement budget.

The seven retained source pages were separately retrieved for verification. One Microsoft viewport omitted the headline, so a second bounded retrieval acquired that missing field. All final retained fields were checked against the actual responses. [Retrieval checks](Retrieval-Field-Checks.json) and [final field checks](Retained-Field-Verification.json) distinguish source acquisition from semantic proof. The same approved tool/orchestration environment was used; no independent semantic model, human factual review or uncached origin retrieval is claimed.

Structured decisions retain claim digest, policy/rule version, concise reasons, passage IDs/hashes/locators, verifier/run identity, source-origin count and bounded attempt fields. No private model reasoning is retained. Nonmatching prose/interpretations/scenarios become unresolved rather than inviting routine factual approval from Rob. Deterministic checks do not invoke a model client. The configured attempt cap is two; preflight uses one attempt and stops when more retrieval cannot resolve a missing semantic verifier. Existing establish retry/checkpoint behaviour is preserved.

`ledger.record_decision` stores a receipt in the existing private operations ledger only if the actual complete candidate statement/digest, source programme and identity match. It grants neither promotion nor qualification authority. New government/EU source acquisition is currently a tool-assisted research bridge, not a complete production Researcher source-policy adapter. The old GCA-only programme contract remains closed: cross-programme evidence cannot bypass it. A versioned new-source programme/collector adapter and independent verifier integration are still required before autonomous provider releases.

## Evaluation and calibration

The evaluator was frozen before held-out case construction. Its SHA-256 is recorded and enforced by the evaluation runner. Development examples and the held-out JSON are separate; changing the evaluator invalidates this result and requires a new evaluation protocol.

[Results](Held-Out-Results.json): **35 controlled synthetic support cases**; false acceptance **0/30**, false rejection **0/5**, unresolved **11/35 (31.43%)**. The report includes every case, confusion counts by claim type, exact denominators and reasons. Identical/copy-origin sources are counted once; copying a researcher's retrieval cannot verify it.

**These references are authored logical rubrics over synthetic source propositions, not independent human/model ground truth.** The author is shared with development, the sample is small and structurally constrained, and it is not a representative real-world corpus. Zero errors against these rubrics does not measure research accuracy. The real AWS passage was a development/live demonstration, not a held-out example. General semantic accuracy and independently annotated real-source evaluation remain unmeasured. This is an explicit acceptance gap.

Covered errors include subsidiary/country substitution, stale and superseded support, achieved/ambition confusion, numerical/causal overclaiming, product ownership/alliance/delivery/adoption substitutions, copied retrievals, conflicting source metadata/passages, injection, sensitive data and operation-rights uncertainty. Unsupported natural-language alliance/adoption reasoning is withheld; no generic natural-language understanding is implied by test totals.

## Rights and publication safety

Every retained source separately records acquisition, deterministic extraction, model processing, retention, quotation, indexing and redistribution. Selected Crown-owned text is assessed under the explicit [GOV.UK content terms](https://www.gov.uk/help/terms-conditions) / OGL v3; selected GCA fields use its original content terms. EU-owned decision prose uses the Commission's explicit CC BY 4.0 reuse notice. Attribution and changes/selection are recorded; no endorsement, trademark licence or permission for third-party works is implied.

This assessment covers only short selected own-authority factual passages. Third-party quotes, proprietary attachments, photographs, logos, contacts and personal records are excluded. There is no blanket permission for all official websites or enterprise publications. Corporate reports and register bodies with unresolved processing/reuse scope remain quarantined, not silently ingested. Model-processing permission for these selected licensed passages does not configure a model endpoint or permit unrelated/private content. The source tool's rendered excerpts are retained; original bytes are unavailable and no original-byte hash is fabricated. Full tool responses, including contact fields, are not published.

All public views read only exact-pinned repository assets. No operational database, tenant store, cache or private log is read. No model client, production identity, new paid service or unattended runner is configured. Existing canonical authority, CSRF, session/workspace controls and Pipeline qualification are unchanged.
