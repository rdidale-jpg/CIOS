### Current experience assessment

The existing artwork and serif/forest identity are distinctive and worth retaining. Shared header code centralises product routes but still mixes Home, PESTLE, Explore, specialist/account routes and Sources & method. Industry scenes and participant tables have different densities; enterprise facts are commercially richer than their visual entry points. PESTLE already has image-native six-factor interaction. No protected Command Centre moves into a public scene. The design persona is illustrative and cannot select tenant or authentication scope.

## Accessibility, responsiveness and performance review

- Native HTML anchors, disclosures, skip link, language, heading structure and semantic text destinations. No JavaScript, motion, hover-only controls, canvas or external font dependency. Illustrations are decorative because the adjacent text carries destination/metric meaning; SVG has a titled semantic equivalent.
- Body text is forest on opaque warm-paper surfaces; the dark variant reverses to pale text on forest. Metrics and next actions have quiet solid surfaces to avoid variable image contrast. Visible focus outlines do not depend only on colour.
- Five labelled tools remain visible with compact mobile sizing; 44px minimum target height. iPad orientations, 390/320px and 720px zoom-width are captured. Mobile hides the tiny SVG skyline and retains the full readable grouped links, not a cropped inaccessible diagram.
- Existing artwork is local and byte-preserved. No font/CDN/telemetry request. Asset decode/layout remains a design risk: final implementation should supply responsive image variants, size budgets and image-off text fallback. CSS mask support must be checked on Safari; a plain image/text fallback remains viable. Slow-network timing and screen-reader certification are **not** claimed.
- No form, POST, storage, query-dependent personalisation or authenticated app route exists in this static pack. App permissions, provenance, employer/seller privacy and Pipeline controls are unaffected. Future implementations must test those actual boundaries, not infer security from these static pages.
