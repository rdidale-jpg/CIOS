F3 follows FIG-1 Option B under accepted ADR-010/011/012: permitted analytical candidates can be useful without universal canonical promotion. Source use, factual verification, technical origin safety, private resource authority and optional canonical acceptance remain distinct. Nothing in the new review contract overrides any existing owner.

## Review contract is not permission

`SeriesUseProposal` describes proposed issuer/subject/series scope, exact original prefixes and seed documents, source category, purpose, audiences, separate use classes, terms applicability and retained-review revision, retention/attribution/link conditions, extraction frequency and required owner decisions. Its statuses deliberately exclude accepted/approved/permitted. `SeriesUseRequest` assesses offline metadata; results can only be `owner_decision_required` or `exception_review_required`. Matching a proposed condition never produces `can_use`, admission or canonical acceptance.

The review revision hashes our retained review record, not unavailable original publisher bytes. Future approved recurring-series admission still needs owner-controlled original document identity/class/version verification and source/terms-change handling; request-supplied category, prefix, public status, enabled SourceRecord or reviewer confidence is not sufficient. Current proposals are deliberately scoped to inspected report directories and demonstrate reuse across compatible measurements; they are not proof of recurring corpus permission. Cumulative limits are operating proposals, not legal substantiality thresholds.

No source policy, SourceRecord, collector, source registry, evidence acceptance mechanism, canonical model, matcher, approval engine or Pipeline service is added or replaced. The proposal module is not imported by runtime source admission or Financial routes. `inspect_current_origin` reports only the result of the existing positive-origin function, expressly not rights.

## Explicit finite financial cases

`Reconciliation.mode=reported_statement` requires declared unique income/cost/credit/associate/provision roles, one accounting basis, exact entity/name/perimeter, explicit duration, source version, state, currency/unit/scale and exact signed reconciliation to a separately reported pretax endpoint. It infers no signs, invents no residual and rejects duplicate components/subtotals. Existing `basis_reconciliation` remains the default and retains its different-basis requirement. Assumed/estimated dependencies remain Estimated.

`Derivation.comparison=duration_dates` requires adjacent ordered complete fiscal years aligned to the stated year-end, the same current presented source vintage and all existing definition/entity/basis/perimeter/state/unit guards. Leap-year day counts are retained; 361-day, partial, overlapping, nonadjacent, changed-perimeter and mismatched-calendar comparisons fail. There is no annualisation, FX, cross-bank ranking or executable formula. Both original periods survive the result. Labels are neutral Annual difference / Relative annual difference beside the existing Calculated/Estimated semantic label.

F1's admitted BoE input adapter, exact v1 raw payload/run ID, source gate and projection/persistence authority remain unchanged, proved against [the actual validated F2 record](F1-Compatibility.json). No new default field is added to persisted `Derivation` data. New modes do not admit new issuer input. Synthetic nonproduction tests use actual guarded Financial storage and reload, then prove the fixture becomes unreadable after its test-only source adapter is removed. That is not a genuine named-bank run.

Multi-component bank bridge validation is presently an offline Financial-owner operation. There is no new issuer recipe-persistence adapter or schema rollout. A subsequent authorised source integration must pin its genuine input/recipe contract and bind real resource authority; it cannot feed this review pack to a caller-controlled permission parameter.

## Preserved boundaries

All historical research, source identities, owner decisions, original assets and accepted stream/navigation contracts are unchanged. BoE source withdrawal/current rights/revision checks still run before Main/title/table/ARIA/detail output. Research-only figures are absent from those paths. Original source/tenant/Offer/Pipeline controls stay fail-closed. No production/canonical writes or deployment operations occur.
