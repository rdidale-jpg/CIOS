## Verified downloaded-file import

Use `tools/import_flora_primary_source.py` when an owner/researcher has verified an official downloaded original. It accepts PDF, UTF-8 HTML or text, with a bounded size. It performs **no network request** and is not exposed as a public upload endpoint.

1. Verify the original publisher URL, document/version, publication date, reporting period and exact supporting passage. Record reviewer limitations; a checksum alone cannot establish publisher authorship.
2. Copy [the metadata template](Source-Import-Metadata.example.json). Supply the actual download checksum (`sha256sum <file>`), UTC retrieval timestamp, original and resolved HTTPS URLs, provenance attestation, publication-date evidence (or null), and reviewed quotation/location. Do not mark a landing page as a report or a forecast as an actual.
3. Run:

   ```sh
   python tools/import_flora_primary_source.py --file /path/to/report.pdf --metadata /path/to/review-metadata.json --output /path/to/new-private-scratch-directory
   ```

4. The importer rejects mismatched bytes, unapproved publisher URLs, absent attestation, invalid/future dates and quotations missing from extracted content. It strips HTML scripts/styles and uses existing PyMuPDF for PDF extraction. OCR/table quality still needs review. Output contains original bytes, extracted text and `review-proposal.json` marked `review_ready_not_accepted`; existing destinations and application/repository data directories are rejected.
5. Review the proposal. To integrate a reviewed original later, copy only approved material under `source-snapshots`, retain `raw_path`, `text_path`, original/text hashes, metadata and exact claim quotations. The model verifies original bytes for a `verified_download`; reviewed web extracts explicitly have no original-file hash. Add new stable claim IDs and explicit updates/corroboration. Preserve the prior assessment. This manual Git-reviewed integration does not create accepted canonical Evidence, modify governed memory or qualify a sale.
